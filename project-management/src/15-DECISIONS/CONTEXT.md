# project-management/src/15-DECISIONS

Architecture Decision Records (ADRs) — significant technical and design decisions with
context, options considered, and rationale. One immutable record per decision.

## Directory Tree

```text
project-management/src/15-DECISIONS/
├── CONTEXT.md              ← this file
├── CLAUDE.md               ← operating rules for this folder
├── ADR-US000-TEMPLATE.md   ← ADR template — copy to author a new decision
├── ADR-US###-<DECISION>-DD-MM-YYYY.md  ← one file per decision
├── DECISIONS-BOARD.md                  ← the ADR index — generated by pm-board.sh, committed
├── decisions-board.json                ← generated, gitignored
├── decisions-board.html                ← generated kanban view, gitignored
└── archive/                            ← Superseded and Deprecated ADRs, moved by pm-archive.sh — frozen
```

Example, illustrative only: a decision on opaque session tokens, driven by story 14 and made on
31/08/2026, is ADR-US014-OPAQUE-SESSION-TOKENS-31-08-2026.md.

**Naming:** `ADR-US###-<DECISION>-DD-MM-YYYY.md` — the driving story, the decision it
governs in `SCREAMING-SNAKE-CASE`, and the date it was made. Flat: no per-story
subdirectories. There is no `ADR-###` counter; it was retired 31/08/2026, and the index is the
generated board below.

## What each ADR records

Each ADR captures five sections — **Status** (Proposed / Accepted / Superseded /
Deprecated), **Context**, **Options considered**, **Decision**, and **Consequences** —
under a metadata header (Date, Deciders, Supersedes / Superseded by, Related `US###`). The
`**Status:**` line holds the value alone, with any prose on a `**Status note:**` line beside it;
`**Supersedes:**` and `**Superseded by:**` each hold a full ADR filename or `None`.
The full scaffold with authoring guidance lives in `ADR-US000-TEMPLATE.md`.

## The index

`DECISIONS-BOARD.md` is the register's index: one row per ADR in this folder and `archive/` —
ID (the filename stem), title (the H1), status and file, plus the two supersession columns —
filed under its status in lifecycle order, rows in ID order. It is generated by
`00-ASSETS/scripts/pm-board.sh --write` from those header lines alone. A `Superseded` or
`Deprecated` ADR is archived by `pm-archive.sh <ID>`, keeping its status, into `archive/`. The
vocabulary is owned by `.claude/skills/completion/SKILL.md`.

## When an ADR is written

At the PM step that **surfaces** the trade-off — a schema shape or RLS scope at
`04-database-schema`, a session strategy at `10-security-checks`, a contract shape at
`13-api-design` — not held to the end of the loop. Workflow `15-decisions` is the
**coherence gate**: it checks a story's ADRs hold true and do not clash before
`16-sprint-plans` and `17-story-plans` plan against them.

## Authoring a new ADR

Copy `ADR-US000-TEMPLATE.md` → name it for the driving story, the decision and today's
date → fill the five sections → cross-link the `US###` that drove or consumes it → set
**Status** to `Accepted` on sign-off.
