# WALK-N010 — first cold walk, 31/08/2026

**Node**: `MAP-NAVIGATION.md` N-010 · **Verdict**: FAIL on the token ceiling, PASS on every
question · **Driver**: isolated `claude -p` session, launched by the resolving session

The experiment the navigation epic turns on: can this repository orient an agent that has never
seen it? This file is the raw result, recorded before the map was opened, together with the
independent verification of what the walker claimed. The walker's own words are in
`WALK-N010-COLD-31-08-2026-REPORT.md`; the ground-truth transcript is the `.jsonl` beside it.

---

## How coldness was obtained

`.claude/CLAUDE.md` auto-loads the root `CONTEXT.md` and `REFERENCES.md` through its `@` imports.
Between them they carry the annotated directory tree and the full internal doc index, so **any
session started inside this repository already holds most of what questions 1 and 4 are meant to
cost reads to discover**. The walk budget of "entry file plus two reads" cannot be honoured by a
session the project's own entry path configured.

The walk was therefore run as a separate process with the chain suppressed:

| Control                | Value                                                     |
| ---------------------- | --------------------------------------------------------- |
| Working directory      | `/tmp`, outside the repository — no project chain loaded  |
| Repository access      | `--add-dir` only                                          |
| Tools                  | `Read`, `Glob`, `Grep` — no shell, no write, no subagents |
| MCP servers            | none (`--strict-mcp-config`)                              |
| User-level `CLAUDE.md` | none exists on this machine                               |
| Model                  | Opus                                                      |
| Capture                | `stream-json` — every tool call is ground truth           |

The transcript confirms `cwd` outside the tree and an empty MCP list, so the isolation is a
recorded fact rather than an assurance.

**This is a variance from the ruling that produced N-010**, which reserved the first walk for a
session Sam drives rather than one the resolving session launches. The mitigation is that nothing
here rests on the walker's self-report: the transcript was captured and every load-bearing claim
was checked against the tree afterwards, which is how the false finding below surfaced.

## What the walker did

Rule chosen: **the 300-line instructional file limit and its 270 ratchet**.

| #   | Call                                     | Outcome                                        |
| --- | ---------------------------------------- | ---------------------------------------------- |
| 1   | `Glob *`                                 | ~118k paths, almost all `node_modules/`        |
| 2   | `Glob */*`                               | the call that actually oriented it             |
| 3   | `Read` root `CLAUDE.md`                  | **errored — the file does not exist**          |
| 4   | `Glob {README,CLAUDE,CONTEXT,...}*`      | recursive; returned 100 `node_modules` READMEs |
| 5   | `Read .claude/CLAUDE.md`                 | **read 1** — its entry file                    |
| 6   | `Grep DOCUMENTATION-LENGTH\|docs-length` | 57 hits                                        |
| 7   | `Read code/docs/DOCUMENTATION-LENGTH.md` | **read 2**                                     |

Two reads of the three allowed. All four questions and the inbound direction answered, none
marked `INFERENCE`.

---

## Verdict, and where it actually failed

**The navigation half passed.** Every question was answered from an explicit pointer or a scoped
search, in two reads, and the walker never had to guess. The rule declared its own owner, its own
gate, and its own blast radius, and `.claude/CLAUDE.md` named the target path literally.

**The budget half failed, on tokens, by roughly ten times.**

| Measure                 | Value  |
| ----------------------- | ------ |
| Ceiling                 | 8,000  |
| Output tokens           | 8,446  |
| New context pulled in   | 67,187 |
| New content plus output | ~75.6k |

The walker self-assessed the overspend at about 5,000. That estimate is far too low. The spend was
not reading — it was **reconnaissance**: two unguarded globs against a working tree carrying 64,640
files under `node_modules/`.

---

## The finding that matters most: a confident, false negative

The walker's headline was that `code/docs/CONTEXT.md` never cites the length rule — "the pairing
convention failing on the guide that polices its sibling convention". It is **wrong**.
`code/docs/CONTEXT.md` cites it twice, in the tree block and again in the guide table, the second
with a full-sentence description. The walker's own grep returned those lines; it did not see them
among 57 hits and asserted the negative anyway.

This is the self-grading defect the node was written to avoid, wearing a different face. The
guarded-against shape was _a walker reporting its own success_. The shape that actually appeared
was **a walker reporting a defect that is not there** — and no read budget catches it, because the
walk was inside budget when it happened. A walk test that is not independently verified produces
findings at the accuracy the walker happens to have.

Everything else the walker claimed checks out: the two negative citations where a sibling gate
declines to check length and defers here, the pre-commit call site with its `--since HEAD` baseline,
and the live dated allowance expiring 01/11/2026.

## Two front-door findings, both confirmed against the tree

- **The root `CLAUDE.md` does not exist.** It is gitignored on the expectation that
  `code-review-graph install` generates one, and none was generated here. The cold reader went for
  it first and got an error.
- **`node_modules/` drowns the front door.** `README.md` and `CONTEXT.md` are both present at the
  root and tracked. The walker concluded there was no `README.md` because its filename glob
  returned a hundred vendored READMEs and truncated before reaching the real one. This is sharper
  than what the walker reported: the front door exists, and the search a stranger runs cannot
  reach it.

## Control-defect reachability

The map names four known defects as classes. A walk that misses all four would be evidence the
test is too weak rather than evidence of navigability.

| Class                                             | Reached                                                                           |
| ------------------------------------------------- | --------------------------------------------------------------------------------- |
| Circular attribution — two defer to a third       | **Yes.** It traced a deferral chain and confirmed the third carried it            |
| Script header claiming files it no longer updates | **Within the one unspent read.** Script and both call sites located, never opened |
| A cited destination that was never written        | Class exercised by the inbound question; produced a false positive instead        |
| An index drifted across many maps                 | Not touched                                                                       |

Not all four were missed. **The test is not too weak.**

## What this routes to

The failure is **not navigational**, so it is not an argument for the layer N-004 already refused.
Two things failed, and neither is answered by more documentation:

1. **Approach to the root** — no `CLAUDE.md`, a `README.md` unreachable by search. The cost is paid
   before the first read, which is why the read budget held while the token budget did not.
2. **Verification** — the walk produced one confident falsehood, and only an independent check
   caught it.

Both belong to whatever N-009 becomes if it opens. Recording the outcome against the node, and the
PASS/FAIL routing that follows from a token-only fail, is a judgement about the epic and is made on
the map, not here.
