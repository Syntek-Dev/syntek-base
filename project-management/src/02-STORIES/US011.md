## Client Summary

Four of the project's contents pages were created empty, each carrying a note saying it still
needed filling in. This change fills them: every story, sprint, decision record and implementation
plan gets a line listing what it is, what state it is in and when it last moved, so anyone can see
what the project holds without opening forty-odd files. A new project still starts with those
pages empty, as it should.

---

## User Story

As a **developer or agent opening a register folder I did not fill**, I want **every instance in
it listed in that folder's index with its state and a one-line summary**, so that **I can see what
the register holds and what condition each entry is in without opening every file, and the index
stops declaring an emptiness that is false**.
