# CUT-PLAN — which map slice becomes which story, and in what order

**Last Updated**: 17/10/2026 **Version**: 0.2.0 **Maintained By**: Sam
**Language**: British English (en_GB)

---

**What this is.** The one cut plan across every map in 01-FEATURE-MAPS: for each slice, the story
it becomes, its cut order, size, priority, dependencies and status. It exists so that nobody has
to reopen twenty-one maps to answer "what slice should be what story, and which is next".

**What this is not.**

| Not                      | Because                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A story                  | A number is allocated only when the US###.md is saved (`project-management/workflows/02-story-creation/STEPS.md` Step 3). Every number on a `Settled` row is **provisional** and says so                                                                                                                                                                                                                                                                                                                                                     |
| A sprint record          | Admission belongs to `03-sprint-planning`, one story at a time (P1). A sprint named here past SPRINT-08 is never pre-assigned                                                                                                                                                                                                                                                                                                                                                                                                                |
| The owner of a node      | The map owns every decision and its detail. This file cites map lines and summarises; where the two disagree, **the map wins** and this file is corrected. **One exception:** a round recorded here that its map does not yet record governs the rows it answers, until the cut that back-fills the map. Today that is MAP-RULE-OWNERSHIP's round of 21/09/2026, and two answers of the cut-plan update of 17/10/2026 that their maps do not yet record: P1 over MAP-UPSTREAM-TRACKING.md:534, and Q5's hold on CLAUDE-DESIGN-HANDOFF's rows |
| The map index            | That will be MAP-INDEX.md, which US010 creates                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| A replacement for Step 4 | The map's `Story` column is still back-filled per `02-story-creation` Step 4, in the same change as the cut                                                                                                                                                                                                                                                                                                                                                                                                                                  |

> **This file is syntek-base's own, and copier excludes it.** The template's `_exclude` empties
> project-management/src/ at generation, re-including CONTEXT.md, CLAUDE.md, `*TEMPLATE*` files and
> a short list of named assets (copier.yml:155-188), none of which matches this file — so a
> generated project never receives syntek-base's backlog plan. Write it freely; it never ships.
> Keep TEMPLATE out of its name, or the re-include ships it. <!-- doc-references: template-only -->

**How it is kept current.** A row changes status **in the same change** that cuts, holds or
releases its slice — a cut flips `Settled` or `Proposed` to `Cut` and writes the real number; a
hold or release names the map that caused it. Provisional numbers below a cut shift with it. A
map's round (P4) moves its rows from `Proposed` to `Settled` in the same change as the round.
