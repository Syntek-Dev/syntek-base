## Client Summary

The folder that lists this project's automated quality checks keeps its own index, and that index
is two lines from a hard limit. Nine new checks are due to be built over the coming sprints, and
each needs two lines in it — so the next check to be written cannot register itself, and a check
nobody can find is a check nobody runs. This story makes room by deleting the parts of the index
that repeat rules already stated elsewhere, so the register itself survives intact.

`code/src/scripts/audits/CONTEXT.md` to have room for its inventory and dependencies rows, so that
I can register my gate in the same change that writes it instead of having to shrink someone
else's documentation first.

**The arithmetic, corrected 02/09/2026 (QA-PLAN-US002 AC-GAP-6).** A new audit costs **three**
counted lines, not two: a Directory Tree row, an inventory row and a Dependencies row. Measured in
`code/src/scripts/audits/` on 03/11/2026 at `357db65` — **27 scripts · 29 tree rows** (27 plus the
pair) **· 27 inventory rows · 22 Dependencies rows**, and `CONTEXT.md` at **299** counted lines as
`docs-length.sh` reports it. Eleven planned audits therefore need **33 lines**, and the
Dependencies table is **5 rows short for scripts that already exist**. This story **fills those
five rows itself** rather than budgeting room for them, which is what makes "every register
complete" decidable (AC-GAP-9); the forward demand is then **33 lines**, and a 230 landing leaves
40 below the gate after it — 263. **A landing above 236 fails the dry run**, so the 231–269 band
the first scenario allows is, in practice, 231–236.
