## 1. Summary

Dev nginx answers every `/static/` request from a bind-mounted, empty collected-static directory,
and the dev entrypoint never runs `collectstatic`, so the admin CSS and JS, the project's own
`observability.js` and any story fixture asset all return 404 on the dev stack.

> **Blocks US008.** `../11-QA/IMPLEMENTATION/QA-IMPL-US008-HOST-ONLY-COOKIES-16-11-2026.md` records
> **HP-04 as Fail** on this defect, and its outcome is **Blocked**. Developer ruling, 16/11/2026: this
> bug is fixed **on its own branch, through the `bugfix` skill, before US008's PR is raised**; then
> COOKIE-03, COOKIE-05 and COOKIE-06 are re-walked (HP-04, EC-17), and CLOSE-01 with them.

1. Bring the dev stack up: `bash code/src/scripts/development/server.sh up` (on a fresh checkout,
   or any checkout that has never collected static on the host).
2. Request a file that exists under the static source tree, e.g. `/static/js/observability.js`

## 4. Expected vs Actual

|              | Behaviour                                                                                                            |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| **Expected** | Every file the static finders can locate is served at `/static/` on the dev stack, live from source, with no rebuild |
| **Actual**   | Every `/static/` request returns 404 from nginx; nothing under `/static/` reaches Django                             |

## 5. Root-cause analysis

Two files each assume the other serves static, and neither does.

- **nginx intercepts the route and serves an empty folder.** `dev.conf` aliases `/static/` to
  `/staticfiles/` with no fallback to the upstream, so Django never sees a `/static/` request.
  Compose mounts the host's gitignored collected-static directory there read-only, and nothing in
  dev ever fills it. The comment above the block says "the django container also serves these from
  the finders, so either path works" — false, because the `location` never proxies.
- **The entrypoint skips `collectstatic` on a premise that does not hold.** Its comment says
  "WHITENOISE_USE_FINDERS=True serves static live from source". No settings module sets
  `WHITENOISE_USE_FINDERS`, and WhiteNoise is not in `MIDDLEWARE` (`base.py:48-60`); it is only a
  declared dependency in `pyproject.toml`. What **would** serve live from the finders is Django's own
  `staticfiles_urlpatterns()`, added under `DEBUG` in `config/urls.py` — unreachable behind the
  nginx alias.

| File                                       | Lines | Issue                                                                                                  |
| ------------------------------------------ | ----- | ------------------------------------------------------------------------------------------------------ |
| `code/src/docker/nginx/dev.conf`           | 24-30 | `location /static/ { alias /staticfiles/; }` — no proxy; comment claims a fallback that does not exist |
| `code/src/docker/docker-compose.dev.yml`   | 83    | Mounts the empty host collected-static directory at `/staticfiles:ro`                                  |
| `code/src/docker/django/entrypoint.dev.sh` | 9-10  | Skips `collectstatic`, citing a WhiteNoise finders setting that nothing sets                           |
| `code/src/django/config/settings/base.py`  | 48-60 | No WhiteNoise middleware — so the entrypoint's premise is false                                        |
| `code/src/django/config/urls.py`           | 25-28 | `staticfiles_urlpatterns()` under `DEBUG` — the live server that nginx never forwards to               |

`/favicon.ico` also 404'd in the walk. It is **not** under `/static/` and is proxied to Django,
which has no route for it — a separate, cosmetic absence, not this defect. `TODO(verify)` whether
the fix should add one.

## 6. The fix

Not applied — this record states the smallest fix; the `bugfix` skill lands it on its own branch.

**Approach (smallest):** make dev nginx **proxy** `/static/` to the Django upstream instead of
aliasing it, and drop the dev `staticfiles` mount — Django's `staticfiles_urlpatterns()` then
serves every finder (including django-components' `ComponentsFileSystemFinder`) live from source,
which is what the entrypoint comment intended. Correct both comments to say so. Running
`collectstatic` in the dev entrypoint instead is the rejected alternative: it serves a snapshot,
so a CSS or JS edit would need a restart, and it writes into a host bind mount.
