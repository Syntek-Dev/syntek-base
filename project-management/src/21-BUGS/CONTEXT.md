# project-management/src/21-BUGS

Bug reports, per user story. The base repo ships this folder **template-only** as a
scaffold: one `BUG-US000-TEMPLATE.md` a project copies per defect. Real reports are added
by copying it; nothing else lives here until a bug is filed, bar the generated board.

## Directory Tree

```text
project-management/src/21-BUGS/
├── CONTEXT.md              ← this file (orientation)
├── CLAUDE.md               ← operating rules
├── BUG-US000-TEMPLATE.md   ← copy this to file a bug report
├── BUG-US###-<DESCRIPTOR>-DD-MM-YYYY.md ← a bug a story found, filed under the story that found it
├── BUG-<DESCRIPTOR>-DD-MM-YYYY.md       ← a bug found outside any story's build
├── BUGS-BOARD.md                        ← the bug index — generated by pm-board.sh, committed
├── bugs-board.json                      ← generated, gitignored
├── bugs-board.html                      ← generated kanban view, gitignored
└── archive/                             ← Verified reports, moved by pm-archive.sh — frozen
```

## Where this sits — the record tier

The `src/` folders run in three tiers: **15-DECISIONS → 16-SPRINT-PLANS → 17-STORY-PLANS →
code → 18–22 records**. This folder is a **record** (18-TESTS, 19-REVIEWS, 20-FINDINGS, **21-BUGS**,
22-REFACTORING) — written _after_ code exists, to close the loop on the story plan (17) the
developer coded from. The fix itself ships in `code/`; this folder records the defect, not
the patch.

## What the record captures

One defect per file: metadata (affected story + severity + date found + found-during), the
`**Status:**` line beneath it (`Open`, `Fixed` or `Verified`, any prose on a `**Status note:**`
line), a one-line summary, the environment, numbered reproduction steps, Expected vs Actual, a
root-cause analysis, the fix (files touched + approach), a **regression test** written
test-first (TDD), impact & related stories, and verification via the project test scripts.

## The index

`BUGS-BOARD.md` is the register's index: one row per bug report in this folder and `archive/` —
every `BUG-*.md` but the template, the story-less fallback included — showing ID (the filename
stem), title (the H1), status and file, filed under its status in lifecycle order, rows in ID
order. It is generated by `00-ASSETS/scripts/pm-board.sh --write`. A `Verified` report is
archived by `pm-archive.sh <ID>`, keeping its status, into `archive/`. The vocabulary is owned
by `.claude/skills/completion/SKILL.md`.

## When to write it

File a report when a defect is isolated — during `code/workflows/10-debug/`, or in
`project-management/workflows/11-qa-checks/` / `23-pr-and-review/` review, from a manual
testing guide row that failed at the walk (`22-implementation-documentation` Step 4), or from a
production incident. Copy the template, complete every section, link the story, and flip the
status to `Fixed` (then `Verified`) as the fix lands.
