## Purpose (one line)

The application-side scaling snapshot — per-surface load profiles, the
config-flip-vs-rewrite readiness audit, and the sizing envelope keyed to the
scaling phase-gates — reconciled against live code by the
`scale-planning` skill and consumed downstream by `how-to/src/SERVER-ARCHITECTURE/`
and the `<%DEPLOY_REPO%>` deploy repo.

## How to work here

- **Routing:** all substantive work here enters through the `scale-planning` skill
  (`/scale-planning`). Decisions are charted on
  `project-management/src/01-FEATURE/MAP-SCALE-PLANNING.md` (wayfinder) and settled
  one at a time via `grill-with-docs` — never decided free-hand in a doc edit.
- **Reconcile before you write:** every run first diffs each document against the
  live sources (`code/src/docker/docker-compose.{staging,prod}.yml`,
  `code/src/django/config/settings/`, `config/urls.py`, the ADRs, app
  `CONTEXT.md` files, the deploy repo's modules) and patches drift. If a document
  is missing, regenerate it from the live code — never from memory of a past state.
- **Model:** Fable for envelope/readiness/profile reasoning (it is design work);
  Opus for mechanical reconciliation touches (a changed default, a renamed path).
- **Concrete steps:** reconcile → assess (readiness dimensions, profile shape) →
  grill any open decision → record the settled value with its live-code evidence →
  update `CONTEXT.md` here if the file set changed → hand the envelope numbers to
  `SERVER-ARCHITECTURE/` (buffer applied there, not here).
- **Definition of done:** every stated value carries a live-code citation; TBD
  markers remain TBD unless a grilling settled them; British English; DD/MM/YYYY;
  docs hard-gate satisfied before commit.

## Guardrails

- **Anti-forecast is absolute.** The Postgres horizontal-scaling ADR: "do not
  pre-emptively add infrastructure." Nothing written here may authorise
  provisioning; a target sets trajectory only. Movement between tiers is triggered
  by an observed phase-gate, never by a date or a projection.
- **Never fabricate a number.** No concrete target-user or traffic figure exists in
  this template yet. Tier targets stay `TBD — set via /scale-planning grilling` until
  <%DEVELOPER_NAME%> settles them. A fabricated figure is worse than an honest placeholder.
- **Reference, don't restate.** The cache-stampede, Postgres horizontal-scaling, and
  object-store ADRs, `CORE-AND-SCALING.md`, and the `PERFORMANCE.md` family are
  linked, not copied — a restated table drifts.
- **Scope stops at the app boundary.** Edge duties, TLS/CSP, assigned compute, and
  the headroom buffer belong to `SERVER-ARCHITECTURE/` and the deploy repo. Dev
  operations referenced here go through `code/src/scripts/**/*.sh` only.
- `CONTEXT.md` and this file stay ≤ 300 code lines (instructional); the other five
  are `**/src/*.md` operator guides — exempt, but keep them focused.
