# CUT-PLAN — which map slice becomes which story, and in what order

**Last Updated**: <%DATE%> **Maintained By**: <%DEVELOPER_NAME%>
**Language**: British English (en_GB)

---

**What this is.** The one cut plan across every map in `01-FEATURE-MAPS/`: for each slice, the
story it becomes, its cut order, size, priority, dependencies and status. It exists so that nobody
has to reopen every map to answer "what slice should be what story, and which is next".

**What this is not.**

| Not                      | Because                                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| A story                  | A number is allocated only when the `US###.md` is saved (`project-management/workflows/02-story-creation/STEPS.md` Step 3)     |
| A sprint record          | Admission belongs to `03-sprint-planning`, one story at a time                                                                 |
| The owner of a node      | The map owns every decision and its detail. This file cites map lines and summarises; where the two disagree, **the map wins** |
| The map index            | That is `FEATURE-MAPS-BOARD.md`, generated by `pm-board.sh`                                                                    |
| A replacement for Step 4 | The map's `Story` column is still back-filled per `02-story-creation` Step 4, in the same change as the cut                    |

**How it is kept current.** A row changes status **in the same change** that cuts, holds or
releases its slice — a cut flips `Settled` or `Proposed` to `Cut` and writes the real number; a
hold or release names the map that caused it. A map's interview round moves its rows from
`Proposed` to `Settled` in the same change as the round.

---

## Status legend

| Status     | Means                                              |
| ---------- | -------------------------------------------------- |
| `Cut`      | `US###` saved                                      |
| `Settled`  | The map's interview round is done; awaiting cut    |
| `Proposed` | No interview round yet                             |
| `Held`     | Cuttable, but an open map holds it — named         |
| `Gated`    | The map's own gate box is unticked                 |
| `Blocked`  | Open blocking nodes on a charting or resolving map |

**`~` marks a hint.** An SP or MoSCoW value prefixed `~` is a drafter's estimate, settled at the
map's round or at cut. A value without `~` is settled, or stated by the map with its line cited.
